## 프로젝트 소개

멀티테넌시를 지원하는 온라인 전시회 사이트의 백엔드입니다.
성균관대학교 시스템컨설턴트그룹에서 개발한 프로젝트로, 전반적인 프로젝트 진행과 백엔드 개발을 담당했습니다.

## 개발 동기

기존에는 학생들의 작품을 전시하는 사이트 3개를 따로 관리하고 있었습니다.

처음 하나의 전시 사이트를 완성한 뒤, 다른 종류의 전시 사이트 개설 요청이 들어오면서 기존 코드를 fork해 사용했습니다. 목적과 기능은 물론 코드도 거의 같았지만, 세 개의 소스코드를 따로 관리해야 했습니다.

개발한 지 오래된 사이트라 UI와 UX가 불편하다는 의견도 있었습니다. 유지보수 부담을 줄이고 사용성도 개선하기 위해, 멀티테넌시를 지원하는 통합 전시회 사이트를 만들기로 했습니다.

기존에는 두 학과에서 총 세 개의 전시 사이트를 각각 운영하고 있었습니다. 이 중 한 학과는 전시 목적에 따라 두 개의 사이트를 별도로 운영하고 있었지만, 세 사이트 모두 작품 조회나 카테고리 분류, 게시판 등 대부분의 기능은 비슷했습니다. 이를 하나로 통합하기 위해 Next.js 프론트엔드와 Spring Boot 백엔드를 공통으로 사용하고, 접속한 도메인에 따라 서로 다른 전시를 보여주는 구조로 만들었습니다.

각 도메인은 동일한 프론트엔드 서버로 연결됩니다. 프론트엔드는 서버에서 API를 요청할 때 접속 도메인을 Origin 헤더에 담아 전달하고, 백엔드는 이를 기준으로 전시를 식별합니다. 이후 해당 전시의 작품, 카테고리, 회차, 게시판 등의 데이터를 반환합니다. 덕분에 같은 코드를 사용하면서도 전시별로 콘텐츠와 설정을 다르게 적용할 수 있습니다.

관리자 기능은 별도의 매니저 사이트에서 제공합니다. 관리자 요청은 X-Exhibition-Id 헤더로 작업할 전시를 지정하고, 백엔드에서 해당 전시에 대한 관리 권한을 확인합니다. 전시 데이터와 파일 정보는 MySQL에 저장하며, 이미지와 영상은 MinIO에서 관리합니다. 미디어 파일을 조회할 때는 백엔드의 미디어 API를 통해 제공합니다.



## 주요 작업

- 두 학과에서 운영하던 세 개의 전시 사이트를 하나의 Next.js 프론트엔드와 Spring Boot 백엔드로 통합
- 도메인 기반 멀티테넌시 구현 및 전시별 데이터와 관리자 권한 분리
- 전시, 회차, 카테고리, 작품, 분류, 게시판 등의 API 개발
- 카카오 로그인, JWT 인증 및 작품 좋아요 기능 구현
- 전시별 화면 설정과 관리자 페이지를 통한 콘텐츠 관리 기능 구현
- Excel 기반 작품 일괄 등록 및 MinIO 미디어 업로드 및 스트리밍 기능 구현
- Spring REST Docs를 이용한 API 문서화 및 주요 기능 테스트 작성

## 구현 과정

### 기존 전시 사이트 통합

두 학과에서 운영하던 세 개의 전시 사이트는 목적과 관리하는 데이터가 달랐지만, 작품 조회나 카테고리 분류, 게시판 등 대부분의 기능은 비슷했습니다. 기존에는 사이트마다 코드를 별도로 관리하고 있어 같은 기능을 수정하더라도 각 사이트에 반복해서 반영해야 했습니다.
이를 해결하기 위해 공통 기능을 하나의 프론트엔드와 백엔드로 통합했습니다. 대신 전시별로 도메인과 데이터를 구분하고, 로고나 배너, 수상작 표시 여부, 기본 회차 등의 설정을 다르게 적용할 수 있도록 했습니다.

### 전시별 데이터와 관리자 권한 분리

여러 전시가 하나의 백엔드를 사용하면서 가장 중요했던 부분은 서로 다른 전시회의 데이터가 섞이지 않도록 하는 것이었습니다.
공개 API에서는 Origin 헤더를 통해 접속 도메인을 확인하고, 해당 도메인에 연결된 전시회를 식별하도록 했습니다.
조회된 전시 정보를 기준으로 작품이나 카테고리 등을 조회하기 때문에 같은 API를 호출하더라도 접속한 사이트에 따라 다른 데이터를 반환합니다.
관리자 기능은 전체 관리자와 전시별 관리자로 권한을 나눴습니다. 관리자가 X-Exhibition-Id 헤더로 전시를 선택하면, 백엔드에서 해당 전시를 관리할 권한이 있는지 확인한 뒤 요청을 처리합니다.

### Excel을 이용한 작품 일괄 등록

전시회에는 매 회차마다 많은 작품이 등록됩니다. 작품마다 제목과 발표자 정보, 분류, 이미지, 영상 등을 하나씩 입력하기에는 시간이 많이 걸리기 때문에 Excel을 이용한 일괄 등록 기능을 구현했습니다.
관리자가 Excel 파일과 미디어 파일을 함께 업로드하면, 먼저 Excel의 필수 항목과 전시회 및 회차 정보를 검사합니다. 
이후 Excel에 적힌 파일명과 실제 업로드된 파일을 비교하고, 파일 확장자와 시그니처를 확인한 뒤 작품과 미디어를 등록합니다.
대량 등록 과정에서 일부 파일의 업로드가 실패하거나 DB 트랜잭션이 롤백되는 상황도 고려했습니다. 이미 업로드된 MinIO 객체를 정리하도록 처리해 파일과 데이터베이스 사이에 불필요한 데이터가 남지 않도록 했습니다.

### 대량 업로드 처리 개선

여러 작품을 한 번에 등록할 때 불필요한 DB 조회와 파일 전송이 반복되지 않도록 처리 방식을 개선했습니다.
Excel 안에서 동일한 카테고리나 분류가 반복되면 요청 내에서 조회 결과를 재사용하고, 작품과 분류의 연결 정보는 모아서 저장합니다. 
또한 같은 미디어 파일을 여러 작품에서 참조하더라도 실제 파일 업로드는 한 번만 수행하도록 했습니다.
MinIO로 파일을 전송하는 작업은 별도의 스레드 풀에서 병렬로 처리했습니다. 
이때 DB 작업은 기존 트랜잭션 스레드에서 처리하고, 네트워크 I/O만 분리해 트랜잭션 관리에 영향을 주지 않도록 했습니다.

### 미디어 파일 스트리밍

전시 사이트에서는 이미지뿐 아니라 용량이 큰 발표 영상도 제공해야 했습니다. 
파일 전체를 서버 메모리에 올려서 전달하면 메모리 사용량이 커질 수 있어 스트리밍 방식으로 구현했습니다.
MinIO에서 파일 정보를 조회한 뒤 Spring의 Resource를 이용해 파일을 스트리밍하고, 응답에 Content-Type, 파일 크기, 캐시 관련 헤더를 포함하도록 했습니다. 
이를 통해 파일 전체를 메모리에 적재하지 않고도 이미지와 영상을 제공할 수 있도록 했습니다.

## 장점
전시마다 도메인과 콘텐츠를 따로 관리하면서도 공통 API를 사용할 수 있습니다. 관리자 화면에서 엑셀과 미디어를 함께 등록하고, 작품 조회부터 영상 제공까지 같은 백엔드에서 처리할 수 있게 됐습니다.
